# 给模型的建模指引

这不是强制的建模配方。先判断后续使用者需要什么，再选择表示方式；不要为了“看起来参数化”而增加无用特征。

在这个工场里，供人继续设计和反馈的非标件默认保留原生特征树。只有任务明确是临时包络/占位时，才采用冻结外形；标准件库的装配代理则按其现有契约复用。

## 建模前先确定

从任务说明和接口声明中提取：零件/装配用途、关键尺寸、基准坐标、配合接口、需要重复的元素，以及用户之后可能要求修改或指认的对象。区分：

- **外形占位**：只需在装配中表达包络和接口，后续不会编辑内部建模意图。可使用标准件库；对一次性自定义占位体，冻结 B-rep 也可以，但要说明它不可编辑。
- **可编辑设计**：用户需要调尺寸、理解构造或继续设计。使用 FreeCAD 原生对象；通常以 `PartDesign::Body`、草图、Pad/Pocket、阵列等表达清楚的设计步骤。
- **可按元素反馈**：用户可能说“第 3 个孔/这一个槽不对”。除了特征树，还要提供稳定的语义身份和人可读的对应方式，见“重复元素”。

标准件优先查 `cad3 catalog`，有原生代理就调用 `cad3.parts.add` 并读取声明的 ports；没有原生代理时不要把目录元数据伪装成几何。

## 可读、可编辑的特征树

1. 先定基准和坐标系，再建立主要实体；避免让后续意图依赖偶然生成的 `FaceN` / `EdgeN`。
2. 按功能命名草图和特征，例如 `BoltHoleSeedSketch`、`BoltHoleCut`、`BoltHolePattern`，不要只留下 `Sketch003`、`Pocket004`。对象 `Name` 保持脚本稳定，`Label` 使用简短的人类名称。
3. 将一个设计意图表达成一个可理解的特征组：草图/种子特征/阵列。参数表只放用户确实需要调整的主参数；派生值尽量通过表达式计算，避免重复真值。
4. 如果只需要冻结外形，直接说明，不要声称该形状有可编辑特征树。工程自带 `FeaturePython` 和脚本写入 `Part::Feature.Shape` 都不能替代可重开的原生参数化链。

特征树解决的是**构造意图的可读性和编辑性**。它不自动解决“点击某个孔就能知道它是几号”，也不保证子面编号在改尺寸/重建后稳定。

如 `Name="BoltHolePattern"`，`Label="安装螺栓孔阵列"`；数量/直径以属性和参数源为准。若把“8×Ø14”写进 Label，改数量/孔径时也要更新文字，避免树上的名称变成旧说明。

FreeCAD 1.1.3 的脚本化阵列还需核对 `BaseFeature` 和 `Body.Tip`：对象存在、`pattern.Shape` 正确、`State` 正常，都不证明阵列进入了最终 Body。具体接链示例见 [state-sketch.md](state-sketch.md#6-脚本化阵列要核对最终-body)。

## 重复元素：先选反馈粒度

- 若用户只需修改整个孔系，单个种子草图 + `PolarPattern` / `LinearPattern` 通常最简洁。树节点应明确写出数量、方向/轴和相位由哪些参数控制。
- 若用户会逐个指出实例，阵列的实例通常不会成为各自独立的命名树对象。可为少量关键实例建立独立、语义命名的特征；或保留紧凑阵列，同时在工程中维护稳定元素清单（如 `bolt_hole_03` → 设计坐标、轴向、直径、所属特征），并生成带编号的观察图/索引。
- 清单注明编号规则：例如从零件本地 +X 方向的种子孔起，绕 +Z 逆时针编号。数量、相位、实例顺序改变时说明哪些 ID 保持、哪些被删除或重新分配；不能默认“按当前角度重新排序”就保证保号。
- 选择独立特征还是阵列 + 元素清单，取决于反馈和编辑方式；不要为大量重复孔盲目复制几十个特征，也不要把阵列树节点误称为每个实例均可点名。
- 绝不把 `Face17`、`Edge42` 或当前 GUI 选中序号作为跨重建身份。面编号只可在同一次模型状态中作为临时诊断线索。
- `notes/interfaces.json` 用来记录有装配/功能意义的接口（稳定 ID、对象、坐标、轴、尺寸和含义）；它不是任意拓扑面的永久引用。检查器能证明声明接口在当前 B-rep 上找到候选几何，不代表替人完成了逐个点击寻址。

接口 JSON 是静态文件，改参数表不会自动更新它。由当前参数/Placement 生成接口坐标、尺寸、数量，并同步 `unmated_ok` 等引用；参数修改后重新生成或明确更新声明，再跑 `cad3 mates`。不要把原模型的 8 孔清单继续用于已经改为 6 孔的实体。

当前 `cad3 render` 没有通用 `--labels` 或“点选 → 语义 ID”功能。需要编号图时，用工程脚本根据当前接口坐标和视图投影另行生成并检查；这是工程交付物，不能描述成已经存在的 CLI 能力。

履带驱动轮 v2 是一个参考取舍：名义尺寸由 `Spreadsheet` + 原生表达式驱动；齿槽、螺栓孔、减重孔以单一草图/切除 + 极轴阵列表达，容易整体修改；接口 JSON 为各螺栓孔和履带销座提供了语义名字。它证明原生树与装配接口可以共存，但由于阵列实例不是独立命名节点，**不能**据此声称 FreeCAD 点击任一孔会直接显示其 `bolt_hole_03` 身份。需要逐实例反馈时，要补元素清单/编号图或拆成独立特征。

## 验证与交付

建模完成后根据这个模型的设计意图做验证，不要只依赖通用几何门槛：

- 检查本次运行和完成记录；重算后读 `inspect`，确认 Body Tip、特征依赖链、参数表达式、草图求解状态和原生 Invalid/Error。
- 对编辑性有要求时，把 FCStd 保存后在新的 `cad3 run` 进程中改一个主参数并重算；确认预期特征和最终形状都变化，再恢复并确认回归。复核应在副本中做，或保存进入时的实际单元格内容并在 `finally` 中恢复；不要把脚本初始默认值当成用户的当前值。
- 对装配接口做剖面/等轴测等视觉复核；核对接口声明的坐标轴、材料侧、直径和孔位确实对应几何。
- 用户要按实例反馈时，实际查看编号图/清单是否能让人找到目标实例；不能只检查它“已写入 JSON”。
- 交付时简述：表示方式、哪些参数可改、哪些接口/元素可指认、验证做了什么、哪些细节明确省略。若用冻结形状、简化代理或只有整组阵列，直接说明边界。

给模型的简短任务要求可以这样写：

> 先判断此零件需要占位、可编辑构造，还是逐个实例反馈，再选最简单够用的原生 FreeCAD 表达。若需要编辑，使用按功能命名的草图/特征和少量主参数表达式；对重复元素，明确选择整组阵列或逐项寻址，并提供相应的稳定语义清单/编号视图。不要用 Face/Edge 编号充当稳定 ID。重算后检查特征树、关键接口与图像，并报告简化和不能寻址的部分。
